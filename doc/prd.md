# 移动端 AI Coding Agent 控制台 PRD

## 1. 产品概述

### 1.1 产品暂定名

暂定名：**Agent Console Mobile**

备选名：

* CodePilot Remote
* Agent Cockpit
* Remote Claude Console
* DevAgent Mobile
* Coding Agent 控制台

### 1.2 产品一句话定义

一个面向 AI Coding 重度用户的移动端远程 Agent 控制台，让用户可以在手机、平板上通过 Tailscale 远程连接 Linux 主机上的 Claude Code，会话化地查看项目、输出流、模型、Token、Cost、Context Window、Git 状态、文件触达提示和原生审批状态。

### 1.3 产品定位

本产品不是一个普通聊天机器人，也不是一个简单的消息转发工具，而是一个：

> **移动端 AI Coding DevOps 控制台**

它的核心目标是让用户即使不在电脑前，也能安全、清晰、可控地管理本地主机上的 AI 编程任务。

### 1.4 核心价值

当前很多用户已经开始使用 Claude Code、Codex CLI、Gemini CLI、Cursor Agent 等 AI 编程代理。但这些工具通常运行在电脑终端或 IDE 环境中，用户一旦离开电脑，就很难继续管理任务。

本产品解决的问题是：

1. 用户可以通过手机或平板远程向 Claude Code 发送任务。
2. 用户可以实时看到 Agent 当前运行状态，而不是只能看到一段聊天回复。
3. 用户可以看到当前工作目录、模型、Git 分支、上下文占用和 Token 消耗。
4. 用户可以查看 Agent 修改了哪些文件、执行了哪些命令、是否通过测试。
5. Claude Code 原生需要提权或确认时，移动端可以及时收到并拒绝或挂起处理。
6. 用户可以在移动端切换会话、继续发送输入，并在需要时收到“回到主机继续处理”的降级提示。

## 2. 背景与问题

### 2.1 背景

AI Coding Agent 正在从“代码补全工具”转变为“可执行任务的开发代理”。用户不再只是让模型补一行代码，而是让 Agent 完成完整任务，例如：

* 修复 Bug
* 重构组件
* 优化 UI
* 编写测试
* 阅读项目代码
* 运行构建
* 分析报错
* 生成提交说明

但是这些 Agent 多数依赖本地电脑环境，包括项目文件、终端、依赖、Git 仓库和运行时环境。因此，Agent 的执行能力通常绑定在用户主机上。

### 2.2 当前痛点

#### 痛点 1：离开电脑后无法继续控制任务

用户让 Claude Code 开始执行任务后，如果离开电脑，只能等回到电脑前再查看结果。中途如果 Agent 卡住、需要确认、测试失败，用户无法及时处理。

#### 痛点 2：聊天工具转发不够可观测

类似 cc-connect 的项目解决了“从聊天工具给 Agent 发消息”的问题，但用户看到的大多仍然是消息流，缺少结构化状态，例如：

* 当前 Agent 是否还在运行
* 当前执行到哪一步
* 当前工作目录是什么
* 当前使用的模型是什么
* 当前上下文用了多少
* 本轮消耗了多少 Token
* 当前改了哪些文件
* 当前是否有测试失败

#### 痛点 3：移动端阅读终端输出体验差

Claude Code 输出中可能包含大量日志、diff、命令结果和解释内容。如果原样转发到聊天工具，手机端阅读负担很重，很难快速判断任务是否成功。

#### 痛点 4：远程执行存在安全风险

AI Coding Agent 可能执行以下操作：

* 删除文件
* 修改配置
* 安装依赖
* 执行 Shell 命令
* 修改 Git 状态
* 运行数据库迁移
* 提交或推送代码

如果缺少移动端确认机制，用户很难放心远程运行。

#### 痛点 5：上下文和 Token 不透明

AI Coding 重度用户非常关心：

* 当前上下文是否快满
* 为什么 Agent 越来越慢
* 本轮任务花了多少 Token
* 是否应该压缩上下文
* 是否应该开启新会话
* 哪个项目或任务消耗最多

当前多数工具没有把这些信息产品化展示。

## 3. 目标用户

### 3.1 核心用户

#### 用户类型 A：AI Coding 重度开发者

特征：

* 经常使用 Claude Code、Cursor Agent 等工具。
* 有多个正在开发的项目。
* 经常让 Agent 执行较长任务。
* 关注上下文、Token、模型效果和任务完成质量。
* 希望在通勤、外出、休息时继续管理开发任务。

典型需求：

* 手机上查看 Claude Code 当前任务进度。
* 一键让 Agent 继续修复报错。
* 远程确认 Claude Code 的提权请求。
* 查看本次改了哪些文件。
* 在离开电脑时继续盯住会话状态。

#### 用户类型 B：个人独立开发者 / 小团队开发者

特征：

* 项目数量较多。
* 希望利用碎片时间推进开发。
* 对自动化和效率工具接受度高。
* 不一定需要复杂团队权限，但需要稳定可靠。

典型需求：

* 手机远程推进 side project。
* 让 Agent 修复构建失败。
* 快速查看任务结果。
* 一键生成 commit message。

#### 用户类型 C：产品/设计/前端工作流用户

特征：

* 经常让 Agent 改 UI。
* 更关心可视化结果、截图、布局、交互细节。
* 不一定想看完整代码，但需要看到改动摘要和页面预览。

典型需求：

* 手机查看页面截图。
* 对某个区域提出修改意见。
* 查看 UI 修改前后差异。
* 让 Agent 继续微调布局。

## 4. 产品目标

### 4.1 MVP 阶段目标

MVP 的目标不是做一个全平台、多 Agent、多聊天渠道的大而全工具，而是先验证一个核心闭环：

> 用户可以在手机上通过 Tailscale 连接自己的 Linux 主机，远程控制 Claude Code，并通过结构化状态面板了解任务进展和风险。

MVP 需要实现：

1. 手机端可以通过 Tailscale 连接到 Linux 主机上的本地 Daemon，并看到 Host 在线状态。
2. 用户只能浏览主机端手动添加的项目目录。
3. 用户可以查看项目下的会话列表。
4. 用户可以创建、恢复、切换、重命名 Claude Code 会话。
5. 用户可以向 Claude Code 发送自然语言输入。
6. Claude Code 的输出、工具调用结果和错误信息可以实时流式显示在手机端。
7. 用户可以看到模型、Token、Cost、Context Window；更细的 Context 指标仅在官方接口提供精确值时展示。
8. 用户可以看到项目 Git 状态和当前会话触达文件提示。
9. Claude Code 原生审批或提权请求可以实时转发到手机端。
10. 用户可以拒绝审批请求。
11. 当需要继续执行但手机端无法稳定闭环时，系统会提示用户回到主机处理。

### 4.2 非目标

MVP 阶段暂不追求：

1. 同时支持所有聊天平台。
2. 完整替代 IDE。
3. 在手机端直接编辑大量代码。
4. 复杂团队协作权限。
5. 完整成本账单系统。
6. 多 Agent 自动协作。
7. 云端托管用户代码。
8. Windows / macOS 主机支持。
9. 局域网直连或自建云端中继。
10. 任务级回滚、本轮改动归因、任务完成报告。

### 4.3 MVP 边界结论

为避免第一版范围失控，当前 PRD 明确采用以下边界：

1. 仅支持 Claude Code。
2. 主机端仅支持 Linux。
3. 连接方式优先 Tailscale。
4. 仅允许访问用户在主机端手动添加的项目。
5. 会话是核心实体，不引入 Task 层建模。
6. 审批能力复用 Claude Code 原生机制，移动端第一版只承诺“展示、拒绝、挂起提示”，不额外实现一套自定义审批引擎。
7. `AskUserQuestion` 不作为第一版依赖能力；移动端不承诺通用用户输入卡片。
8. Token 可接受估算值；Context 相关指标仅在 Claude Code 可提供精确信息时展示，拿不到就不展示。

## 5. 核心用户故事

### 5.1 远程启动任务

作为一个开发者，我希望在手机上选择电脑中的某个项目，然后向 Claude Code 发送任务，让它开始修改代码。

验收标准：

* 用户可以看到主机在线状态。
* 用户可以看到可用项目列表。
* 用户可以进入某个项目并创建会话。
* 用户可以发送自然语言任务。
* 会话启动后，Claude Code 输出可以实时返回手机端。

### 5.2 查看任务状态

作为一个开发者，我希望随时看到 Claude Code 当前处于什么状态，避免只看到一段不完整的聊天输出。

验收标准：

* 显示当前状态：Idle / Running / Waiting Approval / Error / Completed / Stopped。
* 显示当前步骤，例如 Planning / Editing / Testing / Fixing / Summary。
* 显示最近执行的命令。
* 显示最近修改的文件。
* 显示任务开始时间和运行时长。

### 5.3 查看上下文和 Token

作为一个 AI Coding 重度用户，我希望知道当前会话上下文用了多少、Token 消耗多少，从而判断是否需要压缩上下文或新开会话。

验收标准：

* 显示当前上下文窗口大小。
* 显示本轮输入 Token、输出 Token，前提是官方字段可得。
* 显示会话累计 Token 或 usage 汇总。
* 显示 Cost。
* 仅在官方接口提供精确字段时展示更细的 Context 占用信息。

### 5.4 查看文件变更

作为一个开发者，我希望知道 Agent 修改了哪些文件，而不是只看自然语言总结。

验收标准：

* 显示新增、修改、删除文件列表。
* 每个文件展示变更类型。
* 优先展示当前会话触达过的文件提示。
* 支持在会话里继续基于这些文件发送自然语言追问。

### 5.5 高风险操作确认

作为一个开发者，我希望 Claude Code 在执行需要提权或确认的操作前，能把原生审批请求转发到手机端，避免我必须回到电脑前处理。

验收标准：

* Claude Code 原生审批请求可以被主机端识别并转发。
* 手机端弹出确认卡片。
* 手机端当前稳定支持拒绝操作。
* 当用户希望继续执行但移动端不能稳定闭环时，系统明确提示回到主机处理。
* 所有确认记录进入审计日志。

### 5.6 多会话管理

作为一个开发者，我希望在同一台主机上管理多个项目、多个 Claude Code 会话，而不是一次只能盯一个任务。

验收标准：

* 同一台主机可以维护多个项目。
* 同一项目可以存在多个会话。
* 手机端可以看到每个会话当前状态。
* 手机端可以在多个会话之间切换查看和继续输入。
* 会话恢复、切换、重命名等能力尽量与原生 Claude Code 保持一致。

## 7. 核心功能需求

## 7.1 主机绑定与连接

### 功能说明

用户需要先在 Linux 主机上安装本地 Daemon，然后在手机端绑定该主机。主机端还需要提供一个本地 Web 管理页，用于登记项目、查看会话和完成基础配置。

### 需求点

* 支持二维码绑定或绑定码绑定。
* 手机端显示主机在线状态。
* 主机端显示已连接设备。
* 支持主动断开设备。
* 支持设备重命名。
* 连接方式基于 Tailscale 网络。
* 主机侧提供本地 Web 管理页入口。

### MVP 建议

MVP 阶段优先支持：

* 本地 Daemon 生成二维码。
* 手机扫码绑定。
* 基于 Tailscale 地址建立 WebSocket / HTTPS 连接。
* 暂不做复杂多设备权限。
* 暂不支持局域网直连。

### 主机侧管理页面

主机侧提供一个仅本机可访问的 Web 管理页，承担以下职责：

* 手动添加项目目录。
* 移除已登记项目。
* 查看当前主机上的 Claude Code 会话列表。
* 执行基础绑定与连接配置。

MVP 阶段不在移动端提供任意目录浏览能力，项目注册入口只放在主机侧管理页。

## 7.2 项目管理

### 功能说明

用户可以在主机端手动添加本地项目目录，在手机端选择项目并启动会话。

### 需求点

* 添加项目目录。
* 显示项目名称。
* 显示项目路径。
* 显示 Git 分支。
* 显示未提交文件数量。
* 显示最近活跃会话。
* 支持移除项目。
* 仅允许访问已登记项目，不能从手机端任意浏览主机文件系统。

### 移动端项目卡片示例

```text
Note Web

branch: feature/mobile-layout
changes: 8 files
last active: 12 minutes ago
```

## 7.3 Claude Code 会话控制

### 功能说明

用户可以从手机端启动、连接、控制主机上的 Claude Code 会话。第一版要求 Daemon 能同时管理多个项目、多个会话。会话模型尽量与原生 Claude Code 保持一致：一个项目目录下可以存在多个会话，会话可恢复、切换、重命名。

### 需求点

* 新建会话。
* 恢复会话。
* 列出当前主机全部可见会话。
* 重命名会话。
* 切换到指定会话。
* 发送用户指令。
* 接收 Claude Code 输出。
* 查看会话历史。

### 会话状态

* Idle：空闲，等待输入。
* Running：正在执行。
* Waiting Approval：等待用户确认。
* Error：执行异常。
* Completed：任务完成。
* Disconnected：主机断开。

## 7.4 实时输出流

### 功能说明

Claude Code 的输出需要实时传回手机端，但不能简单把所有终端文本堆到聊天窗口里。

### 需求点

* 支持流式输出。
* 支持 Markdown 渲染。
* 支持代码块高亮。
* 支持终端输出折叠。
* 支持错误日志折叠。
* 支持长输出自动摘要。
* 支持重要事件转卡片展示。

### 输出类型

* 普通文本
* 思考/计划摘要
* Shell 命令
* Shell 输出
* 文件修改
* Diff
* 测试结果
* 错误信息
* 用户审批请求
* 系统状态事件

## 7.5 状态面板

### 功能说明

状态面板是本产品区别于普通聊天转发工具的核心。

### 显示内容

#### 会话信息

* 会话名称
* 当前 Agent：Claude Code
* 当前模型
* 当前状态
* 开始时间
* 运行时长
* 最后活跃时间

#### 环境信息

* 主机名称
* 操作系统
* 当前工作目录
* 当前 Git 分支
* 默认包管理器

#### 执行信息

* 当前阶段
* 最近执行命令
* 最近错误
* 当前是否等待确认
* 当前是否有未提交变更

#### Token / Context 信息

* 上下文窗口大小
* 本轮输入 Token
* 本轮输出 Token
* 会话累计 Token
* Cost

说明：

* `当前模型` 应优先读取 Claude Code 暴露的真实值。
* `Context` 相关字段仅在 Claude Code 或其 SDK 明确暴露精确值时展示。
* 如果拿不到精确 Context 数据，则移动端直接隐藏这些字段，而不是展示估算值。

## 7.6 Token 与上下文统计

### 功能说明

系统需要记录和展示 Token 消耗与上下文使用情况。

### 需求点

* 按会话记录 Token。
* 按模型记录 Token。
* 显示本轮消耗。
* 显示累计消耗。
* 显示上下文窗口大小，仅在有精确数据时展示。
* 如果官方接口还有更细的 Context 指标，再展示对应值。

### MVP 处理方式

MVP 阶段采用如下策略：

* Token 优先读取官方 usage 字段，必要时退化为估算。
* Cost 优先读取官方字段。
* Context 仅在 Claude Code 可暴露精确值时展示。
* 如果拿不到精确 Context，则不显示 Context 百分比或其他衍生指标。

---

## 7.7 文件变更追踪

### 功能说明

系统需要追踪 Agent 执行期间对项目文件造成的变化。

## 9. 系统架构建议

## 9.1 整体架构

```text
手机 / 平板 Web App
        ↓ WebSocket / HTTPS
Tailscale 网络
        ↓
本地主机 Agent Daemon
        ↓
Claude Code
        ↓
项目目录 / Git / Shell / 文件系统
```

## 9.2 本地主机 Daemon

负责：

* 启动和管理 Claude Code 进程
* 管理多个项目、多个会话
* 维护会话状态
* 读取 stdout / stderr
* 向 Agent 输入用户消息
* 获取当前工作目录
* 获取 Git 状态
* 监听文件变更
* 解析命令和输出
* 估算 Token
* 转发 Claude Code 原生审批请求
* 与移动端同步状态
* 提供主机侧本地 Web 管理页

## 9.3 移动端 Web App / PWA

负责：

* 设备绑定
* 项目选择
* 会话控制
* 聊天交互
* 状态展示
* 文件 diff 展示
* 审批操作
* 推送通知

## 9.4 连接方案

MVP 第一优先方案：

* Linux 主机接入 Tailscale。
* 手机端通过 Tailscale 地址访问主机 Daemon。
* 连接层使用 WebSocket / HTTPS。

后续可选扩展：

* 自建中继服务。
* 非 Tailscale 的其他组网方案。
* 公网设备绑定与转发。

## 9.5 Claude Code 集成策略建议

当前更推荐优先探索官方可编程接口，而不是基于终端文本做脆弱解析。

MVP 建议优先级：

1. 优先探索 Claude Code Agent SDK 或 headless 模式，使用其流式 JSON 输出能力驱动移动端 UI。
2. 会话管理优先复用 Claude Code 原生会话能力，包括 `resume`、`rename`、`switch`。
3. 原生审批优先复用官方权限与用户输入机制，移动端只负责展示和回传，不自研审批语义。
4. 对于模型、Token、Context 等元数据，严格按官方可暴露字段实现；拿不到的字段不虚构，Context 也不估算。

重要说明：

* Agent SDK 路线是官方的可编程集成方式，但使用 API Key 认证，调用与交互式 Claude Code 订阅额度分离。
* Remote Control 路线更接近“继续控制原生 Claude Code 会话”，使用 claude.ai 登录，不依赖 API Key。
* 这两条路线在认证、计费、宿主集成方式上并不等价，开发文档阶段必须先选定主路径。

需要验证的关键点：

* Agent SDK 或 headless 输出中，是否稳定暴露当前模型。
* 会话列表、重命名、恢复能力是否可直接由官方会话 API 驱动。
* 原生审批请求是否可以稳定映射到移动端卡片与用户回传。
* Context 精确值是否能通过官方接口稳定获得。
* 如果选择 SDK 路线，是否接受 API Key 认证与独立计费模型；如果不接受，则需要转向更贴近原生 Claude Code 的集成方式。

## 11. 权限与安全策略

### 11.1 基础安全原则

1. 默认不绕过 Claude Code 的原生审批机制。
2. 用户必须知道 Agent 当前在哪个目录操作。
3. 所有危险命令必须展示原始内容。
4. 用户确认记录必须可追溯。
5. 仅允许访问主机端登记过的项目目录。
6. 移动端与主机端通信需要认证。
7. 不默认上传用户代码到云端。

### 11.2 审批策略

MVP 不自定义低中高风险规则，不试图替代 Claude Code 的安全模型。

系统职责是：

* 接收 Claude Code 原生审批事件。
* 在移动端完整展示请求内容。
* 回传用户操作。
* 记录审批日志。

## 16. 关键风险

### 16.1 技术风险

* Claude Code 的输出格式可能不稳定。
* Token 统计可能难以准确获取。
* Claude Code 是否稳定暴露精确 Context / 模型 / Token 元数据，需要进一步验证。
* Claude Code 原生审批事件如何被 Daemon 稳定捕获，需要技术验证。
* Claude Code Agent SDK 与纯 CLI/headless 方案，哪条更适合作为长期集成层，需要尽快验证。
* Agent SDK 与 Remote Control 的认证和计费模型不同，可能影响产品定位与实现路径。
* Tailscale 网络下的移动端长连接稳定性需要处理。
* 移动端长连接稳定性需要处理。

### 16.2 产品风险

* 用户可能只需要简单聊天转发，不愿使用复杂控制台。
* 状态信息过多可能导致移动端界面拥挤。
* 如果安装绑定流程复杂，会影响转化。

### 16.3 安全风险

* 远程命令执行本身具有高风险。
* Tailscale 节点或绑定设备被盗用可能导致项目被恶意操作。
* 如果把未登记目录暴露给移动端，主机文件系统边界会失控。

## 18. 总结

本产品的核心方向是：

> 从“移动端给 Agent 发消息”升级为“移动端管理 AI Coding 任务”。

它的核心竞争力不应该是支持多少消息平台，而应该是：

1. 让用户看得见 Agent 当前状态。
2. 让用户看得懂 Agent 修改了什么。
3. 让用户知道上下文和 Token 消耗。
4. 让用户能在 Claude Code 请求提权时及时确认。
5. 让用户能在手机上用最少操作继续推进开发任务。

最终目标是成为 AI Coding 重度用户的移动端控制台，让 Claude Code 这类本地 Agent 从“只能坐在电脑前使用”变成“随时随地可管理的远程开发助手”。
